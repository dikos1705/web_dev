# Homework 2: объяснение для защиты

Dayboard продолжает первую домашку. Раньше счётчик жил в браузере и обнулялся после обновления. Теперь можно добавлять, выполнять и удалять задачи. Данные сохраняются в PostgreSQL.

Запуск: положить рабочий `.env` рядом с `compose.yaml`, выполнить `docker compose up -d --build --wait` и открыть http://localhost:8082. Показать добавление задачи с высоким приоритетом, её выполнение и изменения статистики.

`backend` содержит Flask и Gunicorn и обслуживает страницу с API. `database` содержит PostgreSQL. Backend подключается к `database:5432` через DNS сети Compose. `localhost` внутри backend означал бы сам backend. Порт 8082 компьютера направлен на порт 8000 backend; база наружу не публикуется.

`POST /api/tasks` делает INSERT, GET — SELECT, PATCH — UPDATE, DELETE — DELETE. `/api/stats` считает статистику SQL-запросом. psycopg фиксирует успешную транзакцию при выходе из контекста подключения; ошибки приводят к откату. Параметры отделены от SQL-текста.

Healthcheck PostgreSQL использует `pg_isready`. Условие `service_healthy` позволяет backend стартовать после готовности базы. Backend дополнительно повторяет подключение при старте. `/health` проверяет реальную связь с базой.

Volume `postgres-data` подключён к `/var/lib/postgresql/data`: данные находятся вне временного слоя контейнера. Добавить задачу, выполнить `docker compose down`, затем `docker compose up -d --wait`, обновить страницу: задача остаётся. Для сохранения данных volume не нужно удалять.

Для автоматической демонстрации запустить `python verify.py --persistence`: скрипт создаёт собственную запись, пересоздаёт оба контейнера, проверяет запись и удаляет только тестовые данные.

Dockerfile сначала устанавливает зависимости из requirements.txt, затем копирует приложение — это позволяет повторно использовать кеш зависимостей. Процесс запускается от appuser с UID 10001. Gunicorn обслуживает запросы.

`.dockerignore` разрешает в образ только необходимые файлы. `.env` не копируется. `.gitignore` скрывает рабочие env-файлы, но разрешает публичный шаблон `.env.example`. Пароль передаётся через environment, а не хранится в коде. Рабочий файл прикладывается отдельно в систему сдачи.

Изменение POSTGRES_PASSWORD в `.env` не меняет пароль уже созданного пользователя в сохранённой базе. При повторном использовании volume нужно сохранять соответствующую конфигурацию.

Показать Compose, Dockerfile, обработчик POST, именованный volume и результаты `verify.py`. Workflow GitHub Actions повторяет проверки на чистом runner.

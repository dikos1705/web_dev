# Подготовка к защите

## Что я сделал

«Я создал простое веб-приложение на Python, HTML, CSS и JavaScript и упаковал его в Docker. На странице есть счётчик и приветствие, которое сервер читает из переменной окружения APP_MESSAGE. Docker позволяет запускать приложение с нужной версией Python без её установки на компьютере преподавателя».

## Порядок демонстрации

1. Запусти Docker Desktop. Открой терминал в папке проекта.
2. Выполни команды `docker build` и `docker run` из README.
3. Открой http://localhost:8080, покажи приветствие и работу счётчика.
4. Покажи `docker ps`, `docker logs web-homework` и `/health`.
5. Открой Dockerfile и объясни его инструкции по таблице в README.
6. Измени заголовок в HTML, собери версию 2.0 по README и пересоздай контейнер. Обнови страницу.

Если имя `web-homework` уже занято предыдущим запуском этого задания, сначала выполни `docker stop web-homework`, затем `docker rm web-homework`.

## Возможные вопросы

**Что такое image (образ)?** Шаблон файловой системы и настроек, из которого создают контейнеры. В нашем образе есть Python, исходный код и команда запуска.

**Что такое container (контейнер)?** Изолированный экземпляр образа со своим процессом и записываемым слоем. Из одного образа можно создать несколько контейнеров.

**Чем build отличается от run?** `docker build` собирает образ по Dockerfile; `docker run` создаёт и запускает новый контейнер из образа.

**Что означает `-d`?** Запуск в фоновом режиме. `--name` задаёт имя контейнера; `-t` в команде build задаёт имя и тег образа.

**Что делает `-p 127.0.0.1:8080:8000`?** Публикует внутренний порт 8000 на порту 8080 локального компьютера. Браузер обращается к localhost:8080, Docker передаёт запрос приложению на 8000.

**Зачем EXPOSE, если есть -p?** EXPOSE описывает порт в метаданных образа, но сам не открывает доступ. Реальная публикация делается через -p.

**Почему сервер слушает 0.0.0.0?** Чтобы принимать запросы через сетевой интерфейс контейнера. Привязка только к 127.0.0.1 внутри контейнера мешает доступу через проброс порта.

**Что такое переменная окружения?** Настройка процесса, которую можно передать извне без изменения кода. ENV задаёт значение по умолчанию, а `-e APP_MESSAGE="..."` переопределяет его при создании контейнера.

**RUN и CMD — в чём разница?** RUN выполняется при сборке образа. CMD задаёт команду, выполняемую при старте контейнера. Здесь RUN создаёт пользователя, а CMD запускает Python.

**Что такое слои образа?** Образ состоит из слоёв файловой системы. RUN и COPY могут добавлять изменения файлов. Docker кеширует шаги сборки: изменение исходников сбрасывает кеш COPY и последующих шагов, но позволяет переиспользовать предыдущий шаг создания пользователя. Не каждая инструкция создаёт новый слой файловых данных: часть изменяет метаданные.

**Как оптимизирован Dockerfile?** Использован slim-образ; нет лишних зависимостей; копируются только нужные файлы; .dockerignore уменьшает контекст; редко меняющийся RUN находится перед COPY. Приложение работает от непривилегированного пользователя.

**Зачем .dockerignore?** Исключает ненужные файлы из контекста сборки: в образ не должны случайно попадать .git, локальное окружение или секреты.

**Почему изменения HTML не появились сразу?** COPY сохраняет файлы в образ во время сборки. Нужно собрать новый образ и создать новый контейнер. Один `docker restart` старого контейнера не подключает новый образ.

**Где хранится счётчик?** В JavaScript-переменной браузера; после обновления страницы он сбрасывается. Он не хранится в контейнере и не требует volume.

**Что делает HEALTHCHECK?** Периодически вызывает /health и показывает состояние приложения. Сам по себе он не перезапускает нездоровый контейнер.

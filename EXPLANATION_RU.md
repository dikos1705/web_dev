# Объяснение мидтерма: Space Bounty Hunters

## О чём задание

Нужно разработать REST API для космических охотников за головами. Есть справочник разыскиваемых преступников и журнал попыток их поймать. Охотник выбирает цель по награде и опасным признакам, затем записывает результат встречи. Реализация: **FastAPI + PostgreSQL + SQLAlchemy**. Фронтенд по условию не требуется; `/docs` — автоматически созданная документация Swagger.

## Что сделано по критериям задания

| Критерий | Баллы в условии | Где реализован |
| --- | --- | --- |
| Модели и связь один ко многим | 2 | `backend/models.py` |
| Список, детали, совместные фильтры, сортировка преступников | 3 | `backend/main.py` |
| CRUD журнала, проверка данных, автоматическая дата | 3 | `backend/main.py`, `backend/schemas.py` |
| Демоимпорт и Postman-коллекция | 2 | `backend/seed.py`, `postman/SpaceBountyHunters.postman_collection.json` |

Таблица показывает соответствие требованиям, а не обещание оценки преподавателя.

## Как устроена база

`wanted_criminals` содержит ID, настоящее имя (может быть `NULL`), псевдоним, награду, сложность 1–10 и признаки `armed`, `has_crew`, `escape_master`. Последнее местоположение хранится либо как пара `latitude` / `longitude`, либо как текст `location_note`. Ограничение PostgreSQL не допускает неполную пару координат или оба представления одновременно. Награда имеет тип `NUMERIC(14, 2)`, чтобы хранить десятичную сумму без ошибок двоичного `float`.

`hunt_logs` содержит ID, `criminal_id`, результат `success`, заметки `notes`, время `created_at`. Внешний ключ ссылается на существующего преступника. Один преступник может иметь много записей журнала. `created_at` имеет тип `TIMESTAMP WITH TIME ZONE` и значение по умолчанию `now()` на стороне PostgreSQL.

Импорт создаёт 5 преступников и по 2 попытки для каждого — всего 10 записей. Есть неизвестное настоящее имя, текстовые местоположения, координаты и разные сочетания признаков. Повторный запуск не дублирует данные. Проверка пустой базы и импорт выполняются в одной транзакции; advisory lock защищает от двух одновременных импортов. Если справочник уже заполнен, импорт ничего не меняет и не восстанавливает удалённые пользователем журналы.

## Как работают запросы

Пример: `GET /api/criminals/?min_reward=5000&armed=true&sort=-reward`. SQLAlchemy формирует SQL с условиями `reward >= 5000` **И** `armed = true`, затем сортирует награду по убыванию. Можно одновременно передать верхнюю границу и остальные признаки. Значение `false` тоже учитывается: код проверяет `value is not None`, поэтому ложный признак не теряется.

`POST /api/hunts/` сначала проверяет преступника, затем сохраняет попытку. Возвращает `201 Created`, созданную запись и заголовок `Location`. Поле даты клиент передать не может: лишние поля запрещены. База генерирует дату автоматически.

`PATCH` принимает только `success` и/или `notes`. Отсутствующие поля сохраняют прежние значения. ID преступника и время создания изменить нельзя. Пустой объект, `null`, строка вместо булева значения или пустые заметки дают `422`. `DELETE` удаляет запись и возвращает `204` без тела.

Неизвестный положительный ID даёт `404`; неверный тип, неположительный ID, некорректные фильтры или тело запроса дают `422`. Фильтр журнала по неизвестному преступнику возвращает пустой список — это запрос списка, а не запрос конкретного объекта.

## Где что находится

- `database.py`: подключение к PostgreSQL и отдельная сессия на запрос.
- `models.py`: таблицы, типы, ограничения и отношение один ко многим.
- `schemas.py`: входные/выходные Pydantic-схемы и валидация.
- `main.py`: маршруты API и запуск приложения.
- `seed.py`: автоматическое или ручное заполнение демоданными.
- `compose.yaml`: приложение, PostgreSQL и инструмент Newman.
- `tests/`: проверки на настоящем PostgreSQL во временных схемах.
- `postman/`: коллекция из 26 запросов с автоматическими проверками.

## Как показать работу

1. Запустить проект по README и открыть `http://localhost:8084/docs`.
2. Выполнить список преступников с несколькими фильтрами.
3. Открыть детали выбранного преступника.
4. Создать попытку поимки через `POST`, увидеть ID и дату.
5. Прочитать запись, изменить только `success`, затем только `notes`.
6. Отфильтровать журнал по `criminal_id`.
7. Удалить свою запись и получить `404` при повторном чтении.
8. Запустить всю Postman-коллекцию и показать проверки ошибок.
